# ADR-0007：执行证据回流与知识贡献度度量

- 状态：Accepted
- 日期：2026-08-21（设计基线）

## 背景

所有知识库共享一个尴尬：**没人知道它到底有没有用**。命中率、star 数、卡片数都是过程指标；「Agent 引用了这条知识，任务是成了还是砸了」才是结果指标。2026-08 竞距快照核实：没有任何竞品把执行结果闭环回知识库——这是全场空白。

同时，Agent 系统天然生产最有价值的知识原料：失败。同类失败重复发生，是因为教训死在日志里。

## 决策

1. **EvidenceEvent 作为开放回流协议**：任何 Agent 系统在任务结束后投递结构化事件（用了哪些卡、任务成败、失败特征）；schema 与框架解耦，一个 HTTP POST 或一行 JSONL 即可（[spec/evidence-event.schema.json](../../spec/evidence-event.schema.json)）；
2. **事件即源**：EvidenceEvent 以 `adapter: evidence` 落入 L0——经验知识同样有出处，出处就是那次真实运行；
3. **回流编译器**：失败聚类（≥2 次同类才成卡，防噪声）→ 提议陷阱卡（claims 绑定事件源）→ 与被用卡建 `pitfall / refines` 链接 → **同一套机器闸 + 人工闸**（回流不豁免治理）；
4. **贡献度度量**：对照「引用某卡的任务成功率 vs 未引用的同类任务成功率」，按卡输出贡献度榜单；持续为负的卡自动进 suspect 队列——实战反例是与源漂移、时效过期并列的第三条失效通道。

## 后果

**正面**：

- 知识库随使用变强，且强弱**可测量、可复算**——「战果数据」是机制之外最硬的说服力；
- 陷阱卡自动积累：同类失败第二次发生时，检索就能给出规避；
- 负贡献知识被系统性清退，而不是靠人偶然发现。

**代价（诚实声明）**：

- 贡献度是观察性对照不是随机试验：任务难度分布不均会造成假信号——榜单标注样本量与置信区间，只作 suspect 信号不作自动退役依据；
- 依赖消费方如实回传 `cards_consulted`——SDK/MCP 层自动记录引用，减少接入方负担；
- 回流通道是投毒面——限长、扫描、聚类阈值、两道闸四重防线（[威胁模型 §2.③](../security/threat-model.md)）。

## 被否决的替代方案

1. **用检索命中率代替贡献度**：命中 ≠ 有用，过程指标无法回答价值问题；
2. **Agent 任务后直接写经验卡**（自动写入）：违背 ADR-0006 只读原则；经验未经聚类与治理，一次偶然失败就成卡是噪声放大器；
3. **人工事后复盘录入**：有价值但不可规模化，且丢失结构化归因（用了哪些卡）；作为补充渠道保留，不作为机制主体。
