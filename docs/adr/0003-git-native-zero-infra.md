# ADR-0003：纯文件 + git 原生，零重基础设施

- 状态：Accepted
- 日期：2026-08-21（设计基线）

## 背景

平台型知识库（RAGFlow / Dify 类）默认携带 ES、向量库、对象存储、多容器编排。对个人与小团队：

- 部署与维护成本压倒使用价值；
- 知识被锁进数据库，失去 diff / review / blame / revert 的文本工作流；
- 「事实源在数据库里」意味着治理要自建一整套审计与权限。

## 决策

1. **事实源永远是纯文本**：卡片（Markdown + YAML）、源 meta（YAML）、证据（JSONL）、审计（append-only 文本）；
2. **一个 vault = 一个 git 仓库**：知识变更即 PR，人工抽查闸即 code review，CI 即治理；
3. **索引是纯生成物**：`_index/` 可随时重建并逐字节校验；加速后端（SQLite FTS5 / pgvector）是可插拔缓存，**永远不是事实源**；
4. `git clone` 后零服务依赖即可 lint / search / read（M0 验收线）。

## 后果

**正面**：

- 治理工作流零成本复用 git 生态：diff 即审计、blame 即溯源、revert 即回滚、PR 讨论即裁决留痕；
- 可离线、可自托管、可长期保存（纯文本的寿命 > 任何数据库格式）；
- 陌生人上手成本 = clone + pip install。

**代价（诚实声明）**：

- 大规模（10 万卡级）纯文件扫描会慢——用可插拔 IndexBackend 承接，10k 卡 P95 < 200ms 是 M4 红线，更大规模是后端问题不是形态问题；
- 二进制原件会撑大仓库——git-lfs 或内容寻址外部目录（`vault.yaml` 配 blob 根）；
- 并发写入依赖 git 合并语义——知识编译是批处理场景，接受之。

## 被否决的替代方案

1. **数据库为事实源 + 文本导出**：导出物必然漂移；治理必须自建；违背「对人是文档」支柱；
2. **自研存储格式**（AttestDB 的 LMDB 路线）：防篡改哈希链可以要，但代价是失去整个 git 工具链——我们用「git 历史 + append-only 审计」达到足够的防篡改性；
3. **Notion / 数据库类 SaaS 为底座**：供应商锁定 + API 限速 + 不可离线，全部违背设计宣言第五条。
