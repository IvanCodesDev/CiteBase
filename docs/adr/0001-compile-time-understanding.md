# ADR-0001：编译期理解，而非检索时理解

- 状态：Accepted
- 日期：2026-08-21（设计基线）

## 背景

Agent 需要外部知识时，主流做法是检索时理解（Agentic RAG）：查询到达后检索原始语料 chunk，交给模型即时消化。该路线有三个结构性问题：

1. 理解成本 O(查询数 × 语料复杂度)，同一份语料被反复「重新读懂」，成本永不摊销；
2. 幻觉面暴露在每一次检索-生成循环，语料质量无治理；
3. 知识不沉淀：本次任务的教训不会变成下次任务的输入。

## 决策

把「理解」移到编译期一次性完成：LLM + 校验器 + 人工抽查闸把原始语料**编译**成结构化知识卡片；检索期只消费已验证结论，原始语料不进消费方上下文。

类比：原始语料是源码，卡片是二进制，编译器负责优化与验证。运行时（检索时）不再解释源码。

## 后果

**正面**：

- 理解税只付一次；检索期 token 成本可预算（summary 契约 + 渐进披露）；
- 质量控制集中在编译期两道闸，幻觉面从「每次查询」收敛到「每次编译」；
- 知识成为一等资产：可版本化、可审计、可治理、可随执行进化。

**代价（诚实声明）**：

- 编译有前置成本与延迟：新语料从进库到可检索有编译窗口；
- 编译产物可能过时——必须配套漂移审计与失效总线（本决策强制依赖 [出处与漂移治理](../governance/provenance-and-drift.md)）；
- 长尾冷门内容可能不值得编译：接受「未编译内容检索不到」，用无命中契约显式暴露缺口，而非静默兜底。

## 被否决的替代方案

1. **纯 Agentic RAG**：见背景三缺陷；
2. **混合模式（检索不到时实时读原文）**：否决——静默回退会让「库内知识」与「即兴理解」不可区分，摧毁可追责性；缺口应显式暴露并回流为建卡待办；
3. **只做缓存（查询结果缓存）**：缓存键是查询不是知识，无法治理、无法互链、无法回流。
