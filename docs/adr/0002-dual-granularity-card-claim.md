# ADR-0002：卡片 + 论断双粒度合一

- 状态：Accepted
- 日期：2026-08-21（设计基线）

## 背景

知识单元的粒度存在两难：

- **页面粒度**（llm-wiki / Accreta 路线）：人可读性好，但论断混在叙述里，无法逐条验证、逐条失效、逐条引用；
- **claim 粒度**（AttestDB / LLM-Ledger 路线）：机器可验性好，但失去人可读的叙述层与 git 文档工作流，知识变成数据库行。

2026-08 竞距快照显示两条路线各有项目，但没有人同时解决两端。

## 决策

**卡片是读取单元，论断是验证单元**，合一于同一份 Markdown 文件：

- 卡片 = Markdown 正文（Pack 定义分节）+ YAML frontmatter，服务人与 Agent 的阅读；
- 论断 = frontmatter 里的 `claims[]`，每条绑定 ≥1 个 SourceSpan（源 id + 位置 + 片段哈希），服务验证、失效、引用；
- 正文用 `[c1]` 交叉标注引用论断；验证链永远直达源，不经过转述。

## 后果

**正面**：

- 人读卡片、机器验论断、交付物引论断——三个消费场景一份文件；
- 失效可以精确到论断级（一条论断过期不必废整卡）；
- `knowledge_quote(claim_id)` 能返回可核引用，这是页面粒度做不到的。

**代价（诚实声明）**：

- 论断结构化有编译成本——必须配套成本纪律：背景叙述不建 claim，只有会被下游引用、比较、裁决的事实才升格（[对象模型 §5](../architecture/object-model.md)）；
- frontmatter 变重，手写卡片门槛升高——用 `vault init` 模板与 lint 报错信息缓解。

## 被否决的替代方案

1. **只有页面 + 行级引用**（Accreta 路线）：行级引用绑定的是「页面的某行」，页面重写后引用失锚；论断作为稳定 id 的对象才能跨版本追踪；
2. **只有 claim 库**（AttestDB 路线）：丢失叙述上下文与 git 工作流；「何时用 / 怎么用」这类操作性知识不是原子事实，塞不进 claim；
3. **卡片与 claim 分文件存储**：双文件同步是持续出错点；合一文件让 PR diff 一次呈现全部变更。
