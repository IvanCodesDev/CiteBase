# ADR-0004：否决自动实体图谱，受控谓词链接代替

- 状态：Accepted
- 日期：2026-08-21（设计基线）

## 背景

GraphRAG 路线主张：用 LLM 自动从语料抽取实体与关系，构建知识图谱，检索时做图遍历增强。这一路线在 2024–2025 被大量尝试，公开评测（如 GraphRAG-Bench 类）与工程实践反馈一致指向三个问题：

1. **噪声高**：自动抽取的实体粒度不稳定、关系不可靠，图越大垃圾越多；
2. **不可解释**：图中一条边为什么存在，无法向人类解释与追责；
3. **无法人工治理**：百万级自动边没有任何团队能逐条评审，治理承诺形同虚设。

## 决策

不做自动实体图谱。卡片间关系用**受控谓词的类型化链接**承接：

- 谓词表由 Ontology Pack 声明（`used_in / pitfall / refines / cites …`），封闭可枚举；
- 链接由编译器**建议**、经两道闸入库——每条边都过了与卡片同级的治理；
- 链接不承载论断：需要证据的关系必须落回某张卡的 claims（验证责任永远在论断层）；
- 图遍历能力保留：`knowledge_follow` 沿受控边跳读，链接图是检索漏斗第三跳。

## 后果

**正面**：

- 每条边可解释（谓词语义明确）、可追责（经闸入库）、可治理（数量与卡片同数量级）；
- 保留图检索的实用价值（邻域扩展），丢弃图构建的噪声源。

**代价（诚实声明）**：

- 放弃了自动图谱理论上的「跨文档隐式关联发现」能力——接受：那类发现的信噪比不适合作为**治理型**知识库的自动写入，可作为编译器的候选建议输出（仍需过闸）；
- 谓词封闭表可能不够用——由 Pack 扩展，扩展本身是显式的、版本化的。

## 被否决的替代方案

1. **GraphRAG 全自动图谱**：见背景三问题；
2. **无类型自由链接**（wiki 式 `[[链接]]`）：可读但不可查询语义；`follow(predicate=pitfall)` 这类精准跳读需要类型；
3. **图数据库存储**（Neo4j 类）：链接量级（与卡同级）用邻接表文件足够，引入图数据库违背 ADR-0003。
