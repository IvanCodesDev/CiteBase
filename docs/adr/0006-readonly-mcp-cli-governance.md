# ADR-0006：Agent 只读 MCP，人类 CLI 治理

- 状态：Accepted
- 日期：2026-08-21（设计基线）

## 背景

把知识库暴露给 Agent 时，最诱人的设计是「读写都给」：Agent 自己查、自己写、自己修，全自动进化。但这条路在治理上不可守：

- Agent 写入 = 幻觉直通事实源；
- Agent 裁决矛盾 = 把「听谁的」交给最不该拍板的一方；
- Agent 复核失效 = 机器自我平反，审计链失去意义。

## 决策

**读写分权，通道分离**：

- **Agent 走 MCP，只读**：`knowledge_search / read / follow / quote` 四工具；MCP Server 不暴露任何写入与治理动词；
- **人走 CLI 治理**：`compile / drift / audit / resolve / review` 只存在于 CLI；编译产物以 PR 形式过人工抽查闸；
- **Agent 影响知识的唯一合法通道是证据回流**：投递 EvidenceEvent（结构化、限长、过扫描），经回流编译器 + 两道闸才可能成卡——影响力有，直写权没有；
- 边界由**包依赖关系**强制：mcp 包不 import compiler；治理动词的实现根本不在 MCP 进程里。

## 后果

**正面**：

- 攻击面收窄：劫持 Agent 拿不到写权限；投毒必须过两道闸 + 聚类阈值；
- 审计链完整：每次写入都有人类责任人（PR merge / CLI 裁决留痕）；
- 权限模型简单到不需要权限系统：读者与治理者的边界就是协议边界。

**代价（诚实声明）**：

- 知识更新有人工延迟：从证据到陷阱卡最快也要一次人工抽查——接受，这正是质量的来源；
- 高吞吐场景（每天数千事件）人工闸会成为瓶颈——用聚类阈值与抽样率自适应缓解，且抽样率下限不为零（治理永不裁员，见 R2 接受声明）。

## 被否决的替代方案

1. **MCP 提供写工具（agent-writable KB）**：见背景；竞品中提供写入的，治理章节均为空白，这不是巧合；
2. **Agent 写入进隔离区、人工批量放行**：本质还是两道闸，但多了一个「隔离区」概念与状态——证据回流通道已经覆盖此需求，不重复建设；
3. **按角色细分 MCP 权限**（只读 Agent / 可写 Agent）：需要身份与权限体系，违背 v1 边界（一个 vault = 一个 git 仓库）。
