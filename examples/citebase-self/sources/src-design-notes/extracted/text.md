# Citebase 设计要点（自举笔记）

## 编译式定位

Citebase 把「理解」前置到编译期：源材料先编译成结构化卡片，检索直接复用已蒸馏的结论，而不是每次提问都重读全量语料。
与查询期增强的 RAG 不同，编译式知识库的交付物是长期维护的知识资产：卡片、论断、出处与审计记录都是 Git 里的文件。
知识单元是卡片与论断双粒度：卡片面向人的阅读与检索，论断面向机器的出处绑定、哈希核验、状态流转与矛盾裁决。
每条论断绑定源位置（loc）与内容哈希（span_sha256），quote 时重读源文本并重算哈希，源片段被改动无法静默通过。

## 内核边界

内核（lint / index / search / eval）全程不调用 LLM，compiler 是唯一会调用 LLM 的子包。
cards/ 是事实源并纳入版本控制，_index/ 是可随时重建的构建物，SQLite 仅作本地加速缓存。
mcp 子包只读，不得 import compiler；治理动词（drift / audit / resolve / compile）只在 CLI。
内核零领域词：领域语义只准住在 Pack；垂直需求一律进 Pack / Adapter，内核膨胀即失败。

## 检索漏斗

检索拆成四个只读动作：search 返回候选卡摘要，read 读卡片全文，follow 沿受控关系跳邻居，quote 取论断源片段并核验哈希。
检索默认排除 suspect / superseded / retired 状态的卡片；无命中时返回显式降级信号，禁止用模型内化知识冒充库内知识。

## 治理生命周期

drift 聚合源修订变化、span 哈希不匹配与时效过期信号，只把受影响卡片标记为 suspect，从不自动改写或删除知识。
机器提出并拦截，人来裁决：无出处论断被质量闸拒绝；矛盾、合并候选与 suspect 卡进入人工工作流。
矛盾卡由编译器检测并记录，但哪一方正确永远由人工 resolve 裁决。
新源的草稿默认全量人工审核，源的通过率稳定后普通草稿的抽样率逐步下降；合并候选与矛盾卡永远人工处理。

## 联邦

vault 依赖用 vault.lock 锁定（resolved_rev + 逐卡内容哈希），跨库卡片以 <vault-id>::<card-id> 标识。
升级依赖是显式的 lock 文件变更，上游内容永不静默传播。
